# Практика 4. Общее PID-пространство с хостом

Уязвимость реализована в `compose.yaml` у сервиса `host-pid-view` параметром `pid: host`. Контейнер перестаёт использовать отдельное PID namespace и видит таблицу процессов хоста. Остальные ограничения образа остаются включёнными, поэтому видимость процессов не означает автоматическое выполнение кода от root хоста.

`/app/app.py` показывает PID и PID namespace процесса через `/api/status`. В `host-pid-view` пользователь контейнера может получить `PermissionError` при чтении namespace процесса PID 1; сравнивайте поле `self_pid_namespace` и видимость маркера, а не требуйте от API прочитать `/proc/1/ns/pid`. `/app/marker.py` в контейнере `host-marker` оставляет безопасный процесс-маркер. В изолированном экземпляре он не виден в `/proc`, а в `host-pid-view` появляется в общей таблице. Цель — построить Falco-правило на факт выполнения процесса в общем PID namespace, не привязываясь к конкретному PID.
