# Практика 4. Общее PID-пространство с хостом

Уязвимость реализована в `compose.yaml` у сервиса `host-pid-view` параметром `pid: host`. Контейнер перестаёт использовать отдельное PID namespace и видит таблицу процессов хоста. Остальные ограничения образа остаются включёнными, поэтому видимость процессов не означает автоматическое выполнение кода от root хоста.

`/app/app.py` показывает PID и идентификаторы PID namespace через `/api/status`. `/app/marker.py` в контейнере `host-marker` оставляет безопасный процесс-маркер. В изолированном экземпляре он не виден через `ps`, а в `host-pid-view` появляется в общей таблице. Цель — построить Falco-правило на факт доступа к общей таблице процессов, не привязываясь к конкретному PID.
