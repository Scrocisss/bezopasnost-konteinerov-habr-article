# Практика 3. Доступ к Docker Engine через Unix-сокет

Уязвимость состоит из двух частей. В `compose.yaml` сервис `control-center` получает двусторонний bind mount `/var/run/docker.sock` и дополнительную группу владельца сокета через `group_add`. Это даёт процессу возможность отправлять HTTP-запросы Docker Engine, даже если внутри контейнера он работает от UID 10001 и без capabilities.

В образе `container-security-lab/control-center:1.0-vulnerable` обработчик `/app/app.py` выполняет параметр `host` через `/bin/sh`. Через этот уже скомпрометированный процесс можно открыть Unix-сокет и отправить Docker API-запрос. `target-service` без сокета нужен для наблюдения импакта, например остановки соседнего контейнера. Цель — обнаружить успешный `connect` к Unix-сокету и сопоставить его с независимым событием Docker Engine.
