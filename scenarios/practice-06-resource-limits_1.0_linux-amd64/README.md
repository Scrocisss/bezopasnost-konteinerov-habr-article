# Практика 5. Избыточные привилегии

Уязвимость задаётся в `compose.yaml` сервиса `privileged-profile` параметром `privileged: true`. Docker возвращает ему полный набор effective и bounding capabilities, открывает множество устройств `/dev` и отключает `no-new-privileges`. Сервис `default-profile` использует тот же образ, UID 0, `cap_drop: [ALL]` и `no-new-privileges`, поэтому служит контрольным сравнением.

`/app/app.py` только читает `/proc/self/status` и список `/dev`; он не содержит эксплойта. Различие создаёт конфигурация запуска. Безопасный тест монтирует tmpfs только внутри собственного mount namespace: обычный профиль получает отказ, privileged-профиль выполняет операцию. Цель — обнаружить опасную административную операцию и не считать сам UID 0 доказательством `privileged`.
