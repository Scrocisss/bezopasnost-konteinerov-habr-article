# Практика 6. Отсутствие лимитов ресурсов

Уязвимость реализована конфигурацией `unlimited` в `compose.yaml`. У сервиса отсутствуют `mem_limit`, `cpus` и `pids_limit`, поэтому cgroups не задают контейнеру собственные потолки этих ресурсов. `limited` использует тот же образ и приложение, но получает лимиты 64 MiB, 0.25 CPU и 32 процесса для сравнения.

`/app/app.py` показывает `memory.max/current`, `cpu.max` и `pids.max/current`. `/app/load.py` — контролируемый нагрузочный помощник с ограничением аргументов и времени; он не является уязвимостью и не запускает нагрузку автоматически. Для memory используйте 128 MiB на 5 секунд, для CPU — 5 секунд, для PID — 48 процессов на 5 секунд. Цель — связать системные события, OOM и создание процессов с контейнером и явно учитывать границы Falco: сам факт превышения cgroup-лимита может быть виден только через cgroup или Docker telemetry.
