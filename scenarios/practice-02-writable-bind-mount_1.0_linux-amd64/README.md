# Практика 2. Записываемый bind mount

Уязвимая граница реализована в `compose.yaml`. Сервис подключает хостовый каталог `/srv/container-security-lab/practice-02` в контейнер как `/mnt/host-data` с `read_only: false`, хотя корневая файловая система контейнера помечена `read_only: true`. С обеих сторон используется один объект файловой системы, поэтому запись из контейнера изменяет файл на хосте. Основной дефект — доступная для записи точка монтирования, а не UID 0 или capability.

Образ `container-security-lab/writable-bind-mount:1.0-vulnerable` содержит веб-обработчик в `/app/app.py`, который выполняет значение `host` через `/bin/sh`. Эта функция нужна только для контролируемого запуска команды, а нарушение границы задаётся Compose-конфигурацией. Цель — обнаружить успешное открытие файла в `/mnt/host-data/` с флагами записи или создания и отличить его от записи, выполненной процессом хоста.
